### A2 — Хязгаарлалтууд ба үндэслэл

| Утга | Тэмдэг | Үндэслэл |
|---|---|---|
| from = Хүчинтэй | `[property FromOK]` | Бусад утгын нөхцөлд ашиглах шинж. |
| from = Царцаагдсан | `[ERROR]` | Шууд ERROR_FROZEN буцаах тул бусад утгатай хослуулах нь шинэ мэдээлэл өгөхгүй. |
| from = Байхгүй | `[ERROR]` | ERROR_NO_FROM — нэг тест хангалттай, хослуулбал error masking үүснэ. |
| to = Хүчинтэй | `[property ToOK]` | Бусад утгын нөхцөлд ашиглах шинж. |
| to = Байхгүй | `[ERROR]` | ERROR_NO_TO — дангаараа нэг удаа шалгана. |
| to = from-той ижил | `[ERROR]` | ERROR_SAME_ACCOUNT — дангаараа нэг удаа шалгана. |
| amount = Эерэг | `[property Pos]` | Үлдэгдэл, лимитийн харьцуулалт зөвхөн эерэг дүнд утгатай. |
| amount = 0 | `[ERROR]` | ERROR_BAD_AMOUNT — үлдэгдэл/лимиттэй хослуулах утгагүй. |
| amount < 0 | `[ERROR]` | ERROR_BAD_AMOUNT — сөрөг тоо өөр замаар шалгагдаж болох тул тусад нь нэг тест. |
| Үлдэгдлээс бага | `[IF Pos]` | Зөвхөн эерэг дүнд утгатай. |
| Үлдэгдэлтэй яг тэнцүү | `[SINGLE]` | `>` ба `≥`-ийн хилийн утга, нэг удаа шалгахад хангалттай. |
| Үлдэгдлээс их | `[ERROR]` | ERROR_INSUFFICIENT — нэг тест. |
| Лимит дотор | `[IF Pos]` | Зөвхөн эерэг дүнд утгатай. |
| Лимитэд яг хүрнэ | `[SINGLE]` | Лимитийн хилийн утга, нэг удаа шалгана. |
| Лимит хэтэрнэ | `[ERROR]` | ERROR_LIMIT — нэг тест. |
| currency = Ижил | `[property SameCur]` | Хөрвүүлэлтгүй замыг тэмдэглэнэ. |
| currency = Өөр | `[property Convert]` | Хөрвүүлэлтийн замыг тэмдэглэнэ. |

**Тооцоо ("N → M"):**

- Бүрэн олонлог: 3 (from) × 3 (to) × 3 (тэмдэг) × 3 (үлдэгдэл) × 3 (лимит) × 2 (валют) = **486**
- `[ERROR]` утга: 2 + 2 + 2 + 1 + 1 = **8** тест (тус бүр нэг)
- `[SINGLE]` утга: **2** тест
- Үлдсэн хэвийн утгууд: 1 × 1 × 1 × 1 × 1 × 2 = **2** тест
- **486 → 12** (8 + 2 + 2)


### Олон алдааны давуу эрэмбэ

**Эрэмбэ:** `ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT`

**Үндэслэл:** from данс байхгүй эсвэл царцсан бол үлдэгдэл, лимитийг шалгах боломжгүй тул эхлээд данснуудыг (from → to), дараа нь дүнгийн хэлбэр (≤ 0)-ийг, хамгийн сүүлд дансны төлөвөөс хамаарах дүрмүүдийг (үлдэгдэл → лимит) шалгана.

### B1 — Браузерын жишээ (`browser.model`)

| Гаралт | Мөр | Харьцуулалт |
|---|---|---|
| `results/browser-2way.txt` | **10** | Гараар 9 |
| `results/browser-3way.txt` | **20** | Бүрэн олонлог 144 |

**Greedy-гийн тайлбар:** Content × Cookies нь 3 × 3 = 9 хос үүсгэдэг тул 2-way-д 9-өөс цөөн мөр боломжгүй бөгөөд лекц дээр гараар яг энэ доод хязгаарт (9 мөр) хүрсэн. PICT 10 мөр өгсөн нь greedy алгоритм мөр бүрийг "хамгийн олон хамраагүй хос хамрах" зарчмаар нэг нэгээр нэмж, буцаж засдаггүйгээс болсон — хамгийн цөөн covering array олох нь NP-hard тул PICT хурдан, "хангалттай сайн" шийдийг өгдөг ч хамгийн цөөнийг заавал өгөхгүй. 3-way 20 мөр нь бүрэн олонлогийн 144 мөрийн ~14% боловч бүх гурвалсан хослолыг хамарна (доод хязгаар 3 × 3 × 2 = 18).
